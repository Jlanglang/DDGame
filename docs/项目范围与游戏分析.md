# 项目范围与游戏分析（2026-11-16）

> 决定人：主人。本文件是 DDGame 后续投入范围的**唯一依据**，和根 `AGENTS.md` 一起看。

---

## 一、范围决定（2026-11-16）

**继续做深：`doudou`（守护豆豆）、`hero`（豆豆勇者）。**
**其余全部冻结：** `wordtower`、`zombie`、`cardfight`、`rhythm`、`catchalien`、`cube`、`darklegend`、`roadtest`、`stickyfeet`。

冻结的含义：

- **不删、不迁、不重构**，现有代码和线上页面保持原样。
- 不再投入时间改玩法 / 美术 / 新内容。
- 只有「线上崩溃 / 安全」这类事故才动，动完仍然冻结。
- 解冻条件：doudou 或 hero 的「一局完整」验证做完，再评估要不要换项目。

范围收缩的理由（我认同主人这个判断）：

- 11 个游戏全是「机制能跑、但没走完一局」的状态，摊在合集里就是 11 个玩具。
- 做深需要连续投入，一次只能做一个；两个都做等于两个半成品。
- DDGame 的合集约束（零构建、双击玩、程序化美术）适合实验田，不适合当主战场；但先把一个做深，再决定要不要换工程。

## 三、11 个游戏离「一局完整」的分析

> 判断依据：各游戏 `ANCHOR.md` 的「一句话」+ 代码量；**未逐个实玩**。星级是「一局闭环完整度」，不是游戏质量。

| 游戏 | 核心动词 | 一局闭环 | 成长 | 内容量 | 留存钩子 | 做深成本 | 结论 |
|---|---|---|---|---|---|---|---|
| doudou 守护豆豆 | 左右拖 + 自动射击 | ★★★ | 局内卡 | 8 波 + 1 BOSS | 无 | 低 | **继续** |
| hero 豆豆勇者 | 移动 / 攻击 / 技能 | ★★★ | 局内 + 商店 + 存档 | 2 图 + BOSS | 存档 | 中 | **继续** |
| wordtower 单词塔 | 固定炮台 + 选词 | ★★★ | 局内卡 | 100 波 | 无 | 中（词库内容） | 冻结 |
| zombie 大战僵尸 | 点卡种炮 + 阳光 | ★★ | 无 | 3 波 | 无 | 中（关卡） | 冻结 |
| cardfight 卡牌 | 布阵 + 自动战斗 | ★★★ | 英雄升级 + 20 关 | 12 英雄 / 20 关 | 有进度 | 高（美术 / 数值） | 冻结 |

| roadtest 路网原型 | 走路 | — | 无 | — | 无 | 低 | 冻结（本就原型） |
| stickyfeet 黏脚走路 | 走路 / 砍树 | ★★ | 无 | 任务链 | 无 | 中 | 冻结（本就实验） |

**说明（免得把「冻结」误读成「差」）：**

- `rhythm` 的「一局闭环」其实做得最完整（54 关 + 判定 + 评分 + 校准）；它被冻结是因为**做深 = 曲库 / 谱面内容活**，不是玩法深，和「做一个能继续玩的游戏」目标不同。
- `cardfight` 有养成骨架，但 4 个页面 + 3650 行 + 12 英雄，做深是美术 / 数值内容活，投入产出比低。
- `darklegend` 是全场最重（16649 行），已暂停，重启成本最高。
- `roadtest` / `stickyfeet` 本来就是实验场，不是游戏，冻结等于维持现状。
