## 二、路线选择

| 方案 | 做法 | 工作量 | 风险 | 结论 |
|---|---|---|---|---|
| **A. 换皮**（推荐） | 逻辑层完全不动，只替换 `drawMap` 的绘制；程序生成照旧，靠"邻居掩码"自动拼接 | 2～3 天 | 低，一行开关可回退 | ✅ 先做这个 |

## 三、素材规范（直接给 Cursor 用）

### 3.1 硬性约束

| 项 | 规格 | 理由 |
|---|---|---|
| 单格 | **32×32 px**，像素对齐，不许有半像素 | 与 `TILE` 一致，缩放才不糊 |
| 图集 | **每主题一张 512×512 PNG**（16×16 = 256 格） | 单文件 100~200 KB，手机可接受 |
| 背景 | 透明 PNG，**地面瓦片必须满格不透明** | 否则漏出底色 |
| 平铺 | 地面四边必须**可无缝拼接**（上下左右接得上） | 大块地面靠重复 |
| 风格 | **顶视平面**，不做立体高度、不画侧墙立面 | 一做立面就要按 y 排序，实体遮挡立刻变成 bug |
| 色调 | **白天**，对齐比奇城：草地 `#6fb446`、石灰墙 `#d2c6b0`、地图外天空 `#6eb4e6` | 主人定：名字叫暗黑，画面要亮 |
| 细节 | 单格内不要超过 3 个色阶的细节，32px 看不清 | 小尺寸别画细 |

### 3.2 每个主题要画的格子（约 33 张，共 3 主题 ≈ 100 张）

| 组 | 数量 | 说明 |
|---|---|---|
| 地面变体 | 4 | 主用 / 带碎石 / 带草 / 带裂缝，随机撒避免重复感 |
| 墙体 16 组合 | 16 | 4 邻域方向掩码 0~15（详见 §5） |
| 门 / 出口 | 1 | 金光台阶，能被 `drawPortal` 的光晕盖住 |
| 地面装饰 | 8 | 草丛、石块、骨头、水洼、蘑菇、蛛网、裂缝、落叶 |
| 墙面装饰 | 4 | 火把、苔藓、裂缝、铁钉 |

**三个主题**（对应现有等级段，正好和 `ZONE_FLOOR` 的 10 色梯度对上）：

1. `tiles-field.png` —— 村外草地（1–10 级：鸡鸣村外 / 荒田 / 狼谷）
2. `tiles-cave.png` —— 洞窟（稻草垛洞 / 蛛网洞 / 石魔矿洞 / 古墓 / 血蝠洞）
3. `tiles-waste.png` —— 荒原墓地（血月荒原 / 木乃伊墓室 / 恶魔祭坛 / 山贼寨）

先只做 `tiles-cave` 一套，跑通管线再加另外两套。

### 3.3 图集坐标表（`tiles.js` 里的元数据，主人画完按这个填）

```js
// 十六进制 ID = (列, 行)，单元格 32px
const ATLAS = {
  floor:  [0x00, 0x01, 0x02, 0x03],      // 4 个变体，横排在第一行
  wall:   [0x10, 0x11, ..., 0x1F],       // 16 组合，两行排满
  door:   0x20,
  decor:  [0x21 ... 0x28],               // 8 个地面装饰
  wallFx: [0x29 ... 0x2C],               // 4 个墙面装饰
};
```

> 约定：**列号 = ID & 0x0F，行号 = ID >> 4**。这样 Cursor 画完只要说"第 2 行第 3 列"，就能直接换算。

### 3.4 喂给 Cursor 的提示词模板

```text
画一张 512×512 的 32px 像素瓦片图集，透明背景，顶视平面（不要立体侧墙）。
风格：热血传奇比奇城的白天，顶视，颜色要亮，每格不超过 3 个色阶。
参考色：草地 #6FB446，石灰墙 #D2C6B0，台阶金 #F0C840。不要做成夜色。

第 0 行：4 个地面变体（纯色底 + 细微碎石/裂纹），必须四边无缝平铺。
第 1–2 行：16 个墙体组合，按 4 位邻域掩码排列（bit0 上、bit1 右、bit2 下、bit3 左），
          掩码为 0 时是独立石柱，15 时是实心墙块；与地面接触的边要有 1px 亮边和 2px 暗投影。
第 3 行：门（金色台阶）、8 个地面装饰（草丛/石块/骨头/水洼/蘑菇/蛛网/裂缝/落叶）、
        4 个墙面装饰（火把/苔藓/裂缝/铁钉）。

输出：单张 PNG，格子严格对齐，不要画格子线，不要留边距。
```

## 五、自动拼接算法

墙体画不好看，九成是这一步偷懒。规则：

```js
// 对 map=1 的格子算 4 位掩码
// bit0 上 / bit1 右 / bit2 下 / bit3 左
// 邻居越界一律当"墙"（地图边界不画断口）
function wallMask(map, x, y) {
  const W = map[0].length, H = map.length;
  const solid = (nx, ny) =>
    nx < 0 || ny < 0 || nx >= W || ny >= H || map[ny][nx] === 1;
  return (solid(x, y - 1) ? 1 : 0) |
         (solid(x + 1, y) ? 2 : 0) |
         (solid(x, y + 1) ? 4 : 0) |
         (solid(x - 1, y) ? 8 : 0);
}
```

- `mask = 15` → 实心墙块（大部分格子走这条，最快）
- `mask = 0` → 独立石柱（撒障碍生成的单格墙，正好用上）
- 其余 → 靠查表选边角图
- 门（`map=2`）不参与墙体掩码，按墙处理即可

**地面接缝**：地面瓦片本身无缝，但地面与墙交界处统一画一条 2px 暗投影（图集里的墙底边自带），这样格子之间不会"浮"。

**玩家脚下高亮**保留现在的青色描边（`game.js:4147-4152`），画在图之后，不受瓦片影响。

## 六、实现拆解

### M1.64 · 管线打通（0.5 天）✅ 代码已接

**改**：`index.html` 加 `<script src="tiles.js?v=164">`（排在 `world.js` 后面、`game.js` 前面）；新建 `tiles.js`。

**做**：
- `DL.Tiles.load(dir, theme, cb)` —— `new Image()` 异步加载，`onerror` 不抛错
- `DL.Tiles.ready` 标志；未就绪时 `drawMap` 走原来的色块路径
- `ctx.imageSmoothingEnabled = false` —— **注意 `game.js:47-51` 改 `canvas.width` 会重置上下文状态**，必须在 resize 之后重新设一次

**验收**：图集 404 时游戏照常能玩（色块）；图到了之后地面变成瓦片，无需刷新。

### M1.65 · 地面 + 墙（1 天）✅ 第一套是白天草地（比奇城亮度），三主题还没分

**改**：`game.js` 的 `drawMap()`，拆成 `drawMapTiles()` 和保留的 `drawMapFallback()`。

**做**：按 §5 算掩码选图，逐格 `drawImage(atlas, sx, sy, 32, 32, dx, dy, 32, 32)`；地板变体用 `hash(x,y) % 4` 选。

**验收**：
- 主城、`field1`、`cave1` 三张图肉眼看着像"同一个世界"
- 墙的四个角不漏、不断、不错位
- 走到地图四角不出屏（R11.10 回归）

### M1.66 · 三主题 + 装饰（0.5 天）

**做**：`data.js` 加 `THEME_OF_ROOM`；切图时按房间主题切图集；装饰层按 `decorDensity` 确定性撒。

**验收**：进洞窟和进荒原，第一眼能分出来。

### M1.67 · 性能（0.5 天）

**做法**：整张地图预渲染到离屏 canvas（最大 26×26 = 832×832，约 2.7 MB），每帧 **1 次 `drawImage`**，替代现在的视口内逐格绘制。

**注意**：
- 只在 `enterRoom` / 图集加载完成后重建，不要每帧重建
- 相机是平滑的，离屏图要按 `Math.round(cam.x)` 取整绘制，否则瓦片会抖
- 不建整图的话，退一步做 8×8 格分块缓存

**验收**：手机 60fps；`performance.now()` 测 `draw()` 单帧 < 8 ms。

### M1.68 · 主城手工设计（可选，1 天）

主城只有一张、24×24，值得手工摆：石板路、摊位、篝火。用 `genHub` 里现有的 `m[12][x] = 0` 石板路位置改数据即可，不改生成逻辑。

## 七、测试计划

| 层 | 加什么 | 为什么 |
|---|---|---|
| Node 纯逻辑 | `wallMask` 四向/边界/单格柱 16 种组合；`hash` 稳定性；图集 ID → 像素坐标换算 | 这几处错了画面才崩，但 Node 能测 |

**判定**：Node 363 项全过 + 新加纯逻辑项全过 + 真浏览器 2 项通过 = 可以给主人试玩。
