# 卡牌战斗（原型）

横屏 1280×720 的卡牌养成战斗架子：主页面选关 + 布阵 + 英雄池，战斗页按号位自动普攻，怒气技能手动排队或开自动。

## 页面与文件

| 文件 | 作用 |
|---|---|
| `index.html` | **主页面**：20 关关卡列表、进度、出战队伍（点英雄进详情）、布阵入口、英雄池入口 |
| `battle.html` | **战斗页**：`battle.html?level=N` 打第 N 关；只读阵容，不出现详情 |
| `heroes.html` | **英雄池**：12 个英雄一览，已解锁 / 未解锁，品质配色 |
| `hero.html` | **英雄详情**：`hero.html?id=xxx`，立绘 + 等级 / 品质 / 装备 |
| `battle.js` | 战斗页逻辑（布阵读档、开战、回合循环、结算） |
| `formation.js` | 站位规则、可上阵英雄/怪物数据、阵容与进度存档（各页共用） |
| `heroes.js` | 英雄池数据：品质、等级、装备、解锁关卡 |
| `levels.js` | 20 关的敌人排布与成长倍率 |
| `economy.js` | 金币与英雄等级：战斗给金币，升级只花金币 |
| `theme.css` | 品质配色变量与通用品质样式 |
| `combat.js` | 战斗规则：前后排、普攻、打后排/打一排、怒气队列 |

## 品质配色（严格按档位）

| 品质 | 颜色 | 用在哪 |
|---|---|---|
| **A** | 紫 `#b07cff` | 名字、卡框 / 装备框、队伍行边框 |
| **S** | 橙黄 `#ffc451` | 同上 |
| **SS** | 绿 `#63e89a` | 同上 |

- 统一走 `theme.css` 的 `.q-A / .q-S / .q-SS`，取 `--qc`（名字）、`--qline`（边框）、`--qglow-r`（发光半径）、`--qfade`（描边渐变长度）
- **不再显示品质角标**：看名字颜色 + 边框就知道档位（`heroes.html` / `index.html` / `hero.html` 都已去掉）
- 边框是「递增」的：左上角品质色 → 右下角透明（`.q-edge::before` 渐变描边），三档依次变强：
  - 描边粗细 `--qedge`：1 / 1.5 / 2px
  - 品质色沿边延伸 `--qfade`：45% / 70% / 95%
  - 外发光半径 `--qglow-r`：5 / 14 / 26px
- 队伍行的位置文字用 `.pos`（以前误用了 `.slot`，会被布阵板 `.slot` 的 absolute 样式带歪，已修）
- 英雄池卡片、主页面队伍行、布阵托盘都用同一套，不要另写颜色

### 当前档位与解锁

| 品质 | 英雄 | 解锁 |
|---|---|---|
| **A** | 紫垣、极光、银翎 | 初始拥有（`unlockAt: 0`） |
| **S** | 月光、阔刃、余烬、真甲、孤守、残灯 | **只有月光能解锁：通关第 20 关**；其余「暂未开放」（不写 `unlockAt`） |

## 金币与等级

- **英雄等级只能花金币升**，战斗不给经验、不掉等级
- 金币：初始 500（`economy.js`），通关第 N 关奖励 **40 + 12N**；结算卡上会写「金币 +N」
- 升级花费：**30 + 当前等级 × 12**，上限 30 级；详情页「升级」按钮，钱不够时按钮上提示差额
- 主页顶部显示「等级 / 金币 / 进度」；等级 = 初始三位英雄里最高的那个等级
- 存档：`cf.gold.v1`（金币）、`cf.heroLv.v1`（各英雄等级覆盖值）

## 英雄池 / 详情

- `heroes.html`：12 个英雄，6×2 卡片；已解锁可点进详情，未解锁压暗 + 🔒 + 解锁条件
- 解锁规则在 `heroes.js` 的 `unlockAt`；文案统一走 `HeroPool.lockText()`
- `hero.html?id=`：**整张立绘按 contain 全高显示**（左侧，尽量多露），背后垫一层虚化放大的同图补底；右侧面板：名字按品质上色、Lv、攻击 / 生命、4 个装备位、技能描述、升级按钮
- 装备按品质上色；未解锁的英雄装备位显示「未解锁」并压暗立绘
- 主页面点队伍里的英雄 → `hero.html?id=`

## 关卡 / 进度 / 存档

- 20 关在 `levels.js` 的 `RAW` 表里，每关写敌人（怪物 + 号位），数值 = 基础值 × 关卡倍率（生命 +10%/关、攻击 +6%/关）
- 进度存 `localStorage['cf.progress.v1'] = { cleared: [...] }`；第 1 关默认开，通过 N 关后开 N+1
- 阵容存 `localStorage['cf.formation.v1'] = [{ hero, slot }]`，没存档时用默认（紫垣 2、极光 3、银翎 5）
- 结算：赢 → 写入进度；卡片给「返回关卡 / 再打一次 / 下一关」
- 调试参数：主页面 `?edit=1` 直接开布阵层，战斗页 `?debug=1` 暴露 `window.__cf`

## 布阵（只在主页面）

- 入口：主页面右侧「布阵」按钮；战斗页没有布阵
- 板子上是真实的 1280×720 舞台缩放 0.609 倍，5 个圈按站位规则算，敌人以 32% 透明预览
- 拖托盘里的英雄到圈里上阵；拖已上场的英雄到别的圈 = 换位；拖到圈外 = 取消
- 「保存」写入 `localStorage`，战斗页进场时读这份；「取消」丢弃

## 站位规则（定稿）

坐标系：`#stage` 1280×720，`left` / `bottom` 都是 px，原点在左下。**1、3 号格是起点，2/4/5 全由它们推出来**，不单独配坐标。

### X 轴：贴「左切面」

- 2 的中心 = 1 的**左切面**（立绘可见轮廓的左边缘，webp 的透明边不算）
- 4 的中心 = 3 的左切面；5 的中心 = 4 的左切面
- 所以同一排的步进 = 前一张立绘的**可见宽 / 2**（120 高时约 41–46px），角色越宽把后面撑得越开
- 3/4/5 整列再往**对面**挪半个圈：圈宽 72 → 36px（`BACK_FWD`）

### Y 轴：按「身位」排

- 身位 = 立绘高 = **120**（`BODY_H`）
- 3 → 4 → 5：每格 **0.8 身位 = 96px**（`STEP_Y`），越往下越近
- 1 = 3 下方 **0.75 格**（`STAGGER = 0.75`）；2 = 4 下方 0.75 格
- 结果：1、2 卡在 3/4、4/5 之间、偏下 3/4 的位置

### 透视补偿

| 项 | 做法 | 常量 |
|---|---|---|
| 立绘远近 | 按脚位线性缩放：远（y 445）0.86 → 近（y 637）1.0；只缩 `img`，元素仍是 120 高，所以名牌不动 | `DEPTH_FAR` / `DEPTH_NEAR` |
| 纵向格距 | 远格 ×0.92、近格 ×1.08（两格合计仍是 2 格，锚点不动） | `Y_FAR` / `Y_NEAR` |
| 横向步进 | 远 ×0.95、近 ×1.05，略微偏离「严格左切面」2–3px；设 0 即严格贴边 | `X_RAMP` |
| 地圈 | 跟着立绘缩放，并按台面椭圆比 **0.323**（168/520）压扁 | `FLOOR_RATIO` |
| 影子 | `.unit::after` 用同一个 `--s` 系数缩 | — |
| 名牌 | 固定字号/宽度，钉在 120 线上，三排仍然是三条直线 | — |

### 镜像与朝向

- 敌方 = 我方关于 **x = 640** 镜像
- 我方朝右、怪物朝左（立绘本身朝向，不加 `flip`）；所以**敌方的「左切面」在屏幕右侧**，`dir` / `fwd` 按 side 取反
- z 层级按脚位算（越靠下越前），后排不会盖住前排名牌

## 已搁置（2026-10-25）

- **状态：暂停开发**。本作算一次尝试，不再往下推功能。
- **原因：贴图（角色内容）的单位成本付不起。** 一张立绘背后是生成 → 抠图 → 对齐 → 动作帧 → 差分，每环都要人工盯；
  而卡牌养成的核心恰恰是角色内容，不是玩法。
- **结论：卡牌养成 = 「看得见的成长」。** 去掉图和角色内容，就只剩数字对撞；而养成数值本身必须确定（玩家要靠它规划），
  随机只能来自局外的获取 / 分支 / 词缀，单机又因为存档能改而稀缺失真。所以它的价值在陪伴与收藏，不在决策。
- **要重开的话，先解决美术成本，别先加玩法：**
  - 少角色做透：3 个有台词有差分，别 12 个空壳
  - 一张图靠程序化差分撑场：调色、光效、震屏、闪白，不动原图
  - 不画动作帧，做纸片人演出（呼吸 / 晃动 / 位移）
- 三选一升级、局内养成那些别往这里塞 —— 那是 roguelite，是另一个品类。
