## 二、已经改了什么

### 2.1 `game.js`（接入改动，保留）

1. `move(dx, dy)`：删掉了「ThreeView.active 时把输入转给 ThreeView.step」的旧钩子——现在键盘/摇杆走的是真 `P`。

6. `draw()` 在 `ThreeView.active()` 时直接 return（2D 画布被隐藏）。

## 三、已知问题（按优先级）

### P0-1 精灵全部没出来

**现象**：调试面板显示 `group 0`，画面只有地面。
**原因**：`rebuildRoom()` 只在 `roomKey` 变化时调用；它执行时 `DL.Assets` 的图片还没加载完，`frameTex()` 返回 `null`，道具/玩家/NPC/怪都被跳过，之后再也不会重建。
**要改**：加一个 `assetsReady()` 判断（`player/mobs/bosses/npc/pickups` 都 `DL.Assets.ready`），在 `tick()` 里：

```js
if (!spritesReady && assetsReady()) { spritesReady = true; rebuildRoom(); }
```

`rebuildRoom()` 里把 `spritesReady = false` 复位；换房间也复位。

### P0-2 会 dispose 共享纹理

**位置**：`tick()` 里清死亡怪 / 移除袋子时：
```js
if (m.material.map) m.material.map.dispose();
```
`frameTex()` 是**全局缓存**，同一种怪共用同一张帧纹理；这里 dispose 会把别的怪也搞黑。
**要改**：只 `m.geometry.dispose()` + `m.material.dispose()`，**不要 dispose map**。

### P0-3 调试面板要删

`boot()` 里创建的 `global.__dbg3` 面板（左上角 `P 3,12 look...`）是临时调试，删掉。

### P0-4 全局 error 浮层太吵

`render-three.js` 末尾的 `global.addEventListener('error', ...)` 会把任何无关 JS 错误都弹成 3D 出错。建议只在 `boot/tick` 的 try/catch 里弹，或加 `if (!on) return`。

### P1-1 点击/攻击/换房间还没回归

- 点地：`Pick.groundHit(look.x, look.z, ...)` 用的是平滑后的 `look`（也是相机焦点），理论一致；要实测偏差 ≤ 半格。
- 攻击：`strikeAt` 触发 `player-bean` 第 4 列（攻击）；走路用 2/3 列（walk1/walk2）；待机用第 1 列。
  **注意**：当前 `tick()` 里待机写成了 `Math.floor(now/500)%2`（0/1 交替），会像原地踏步；待机应该固定第 1 列（col 0），只有走路才 1/2 交替。
- 换房间：走进门 / 洞口 → `currentRoom` 变 → `roomKey` 变 → 重建地面和实体；要确认出门回城不黑屏。

### P1-2 小地图没了

3D 模式下 `#game` 被 `hidden`，`drawMinimap()` 不再画。需要：
- 方案 A：在 `#view3d` 上叠一个 DOM `<canvas>`，每个房间画一次 `map/seen` 俯视图；
- 方案 B：保留 `#game` 可见但 `opacity:0`，只取它的小地图区域（不推荐）。
先做 A 的最小版：右上角 180×180，画墙/路/玩家点，不做迷雾也行。

### P1-3 传送门/洞口表现

- 主城 3 扇门：`addPortal({kind:'door'})` 现在画金色光圈 + “传送门”，**没区分 1–10 / 10–20 / 20–30**；
- 房间出口：`kind:'exit'` 画青色；
- BOSS 房没有单独标红。
最低要求：门/出口能认出来；名字可以先不画。

### P0-5 移动“一帧一帧”

**不是显卡/帧率问题**（3060 上这场景 GPU 1～2ms），是**位移曲线**问题：

1. 逻辑是跳格：`walk()` 每 `WALK_STEP_MS = 70ms` 调一次 `move()`，`P.x/P.y` 直接 ±1 格；
2. 3D 每帧把 `hero.position` 直接设成 `P.x/P.z`，**没有补间** → 角色每 70ms 瞬移一整格（60fps 下约 4 帧一跳）；
3. 相机 `look` 用 `0.2` 平滑追 `P` → **角色跳、镜头滑**，看起来一冲一冲；
4. 走路帧每 `160ms` 切一次，和 `70ms` 步频不同步；待机还用 0/1 交替，像原地踏步。

**修法（二选一，推荐 A）**：

- **A. 逻辑侧暴露步进进度**：`move()` 成功时记 `{fromX, fromZ, toX, toZ, start, dur: WALK_STEP_MS}`，3D 按 `(now-start)/dur` 在 from→to 之间插值；镜头跟插值后的位置。
- **B. 渲染侧插值**：3D 自己维护 `vis`，按 `dt` 向 `P` 逼近（`k = 1 - Math.pow(0.001, dt)`），镜头跟 `vis`；简单，但和 70ms 步频不完全同步。

另外：
- 相机**只跟一次**（跟 `vis`），不要 `vis` 平滑 + `look` 再平滑；
- 走路帧按移动速度切，待机固定第 0 列；
- 如果还嫌跳，把 `WALK_STEP_MS` 调到 90～110 试手感（会改节奏，需回归测试）。

### P0-6 画面偏“像素感”

**不是错觉，是三个东西叠出来的：**

1. **素材本身是低分辨率**：角色 96×120、怪 96×120、房子 192×224，贴到 128/192px 的面上已经放大 1.3 倍；
2. **过滤方式是最近邻**：`render-three.js` 里 `frameTex()` 和 `texOfCanvas()` 都设了 `NearestFilter`，放大就是硬边马赛克；
3. **每格只有 48px**：1280×720 下 1 格 48px，贴图 1:1 时还行，DPR2 或 zoom 一放大就糊成块。

**修法（按性价比）：**

| 做法 | 成本 | 效果 |
|---|---|---|
| `renderer.setPixelRatio(2)`（桌面超采样，3060 完全吃得下） | 10 分钟 | 立刻细一档 |
| 贴图改 `LinearFilter`（精灵、地面都换；精灵别开 mipmap，会串帧） | 30 分钟 | 去掉硬边 |
| 地面贴图开 `generateMipmaps` + `anisotropy = max` | 30 分钟 | 远处不闪 |
| 每格 48 → **64px**（相机视锥、`three-pick.js` 常量一起改） | 半天 | 像素密度 +33% |
| 素材按 **2× 出**：角色 192×240、怪 192×240、房子 384×448、地面 1024 | 素材批 A 里做 | 真正解决 |

**注意**：
- 精灵图集**不要开 mipmap**（相邻帧会串色），用 `LinearFilter` + `anisotropy` 就够；
- 换 `LinearFilter` 后低分辨率素材会“糊”而不是“块”——**糊比块好，但真正解决还是靠 2× 素材**；
- 别在 CSS 上加 `image-rendering: pixelated`。
