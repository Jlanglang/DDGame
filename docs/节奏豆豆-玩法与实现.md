# 节奏豆豆 · 玩法与实现

> 火柴人跟着音乐做动作。拍准了，动作才落到位。

## 玩法

- 11 关，三种类型：模仿（echo）、卡点（beat）、连打（rush）
- 判定：完美 ±60ms / 不错 ±120ms / 失误 ±200ms
- 校准：跟着 12 下「哒」点，取中位数存本地
- 输入：点屏幕任意位置 / 底部节奏按钮 / 空格、J、F

## 节奏设计

- **普通段**：每小节 1 个卡点（第 1 拍），2 小节最多 3 个
- **高潮段**：每拍或八分，连续八分不超过 1 小节
- **示范 → 跟做**：`d` 是示范（不判定、不计分），`x` 是玩家要按；两段节奏完全一致
- **变化提示**：节奏型切换前一小节加军鼓滚奏，同时屏幕出「变快了」
- **引导音**：每拍一个轻 pluck（音量 0.028）用来数拍子，卡点位置再加一个高八度的重音（0.1）

## 技术

### 时钟

判定只认 `AudioContext.currentTime`，不用 rAF 累积 dt——掉帧不影响判定。

### 判定

- 输入事件的 `timeStamp` 换算回音频时间轴
- 偏差 `dt = 输入时刻 - 音符时刻 - 输出延迟 - 校准值`
- 每个音符只判定一次；超过 miss 窗口的按键算「空按」，不消耗音符
- 漏拍判定留 80ms 余量，防止主线程卡顿把晚到的输入吃掉

### 音频调度

- lookahead 0.5 秒，每 25ms 检查一次，把未来半秒的音排进音频时间轴
- 切后台时 `ctx.suspend()`，音频时钟冻结，回来接着走
- 停止时换一个 master 并淡出旧的，重开不拖尾音

### 音乐

- 全程序化合成（Web Audio），零音频文件
- 每关独立调式和和弦：A 小调五声 / D 自然小调 / E 自然小调 / C 布鲁斯 / F# 和声小调 等
- 鼓、贝斯、琶音由固定编排生成，引导音按谱面铺

## 火柴人

`drawStick(pose, action)` 画圆头 + 线身体 + 四肢，动作靠肢体角度表达：

| action | 动作 |
|---|---|
| clap | 双臂张开 → 胸前合拢 |
| nod | 头下点 + 轻微下蹲 |
| jump | 蹲下 → 起跳（脚离地、影子留地） |
| hit | 举手举棒 → 落手砸下 |
| spin | 横向翻转 + 缩小 |
| lean | 以脚为轴左右倒 |
| pulse | 整体缩放 |
| shake | 左右快抖 |
| catch | 双手举胸前接球（球从天上落到手） |

魔性细节：待机呼吸（±4px）、每 3.2 秒眨眼、拍点缩放 3.5%、判定文字弹入。

## 已知问题

- 偶发卡音：音频节点偏多（每拍引导音 + 鼓 + 音符音），弱机可能扛不住
- 跳绳的绳子现在是个竖直椭圆，像呼啦圈，不是真正的绳子弧线
- 打鼓的火柴人版还没画鼓，只有挥棒动作
- 动作还原度离原版还有距离
