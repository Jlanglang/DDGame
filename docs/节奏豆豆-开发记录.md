# 节奏豆豆 · 开发记录

> 记每个阶段做了什么、踩了什么坑。给以后改这个游戏的人看。

## 阶段 1：圆球豆豆

**需求**：做个节奏天国式的游戏，5 关。

**做法**：圆球 + 两只手，动作靠缩放和位移。

**问题**：

- 「光靠圆脸放大缩小不行」——圆球对称，转圈、摇摆、抖动都看不出来
- 只有「大一点」「小一点」，没有「蹲」「跳」「踢」

**教训**：角色形状决定动作上限。圆球做不出肢体动作，换火柴人是必须的。

## 阶段 2：稀疏化

**需求**：「2 小节里只有 1-3 拍要按」

**做法**：每小节 1 个卡点。

**问题**：

- 音符 1.25 秒就冲到判定线，两个音隔 2.18 秒，跑道大部分时间是空的
- 修：`SPEED` 从 470 降到 360，可见时间拉到 1.6 秒

## 阶段 3：强拍为主

**需求**：「卡点落在强拍，空拍接弱拍才是提高难度」

**做法**：第 1、3 拍为主，反拍只在少数小节出现。

**测试**：强拍占比 ≥ 55%，五关全过。

## 阶段 4：火柴人

**需求**：「要有手脚，动作要看得出来」

**做法**：圆球 → 火柴人（圆头 + 线身体 + 四肢），动作靠肢体角度表达。

**踩的坑**：

- `scenes.js` 里已经有一个 `mix(a, b, u)`（坐标插值），我又加了 `mix(bars)`（节奏型）
- 结果 `PLAN` 调 `mix` 时走进插值函数，崩在 `a[0]` 是 undefined
- 改名 `groove` 解决

**教训**：在已有文件里加函数，先 grep 名字。

## 阶段 5：接球关

**需求**：「物件本身是提示」

**做法**：球从天上掉到手里，球到手 = 拍点。

球的位置不是随便飘的：

```
球 y = 手的位置 - 剩余秒数 × 430
```

剩余秒数取自「距下一个未判定音符」，和判定同一个时钟，所以球和判定严格同步。

## 阶段 6：材质打击声

**需求**：「音乐素材要符合场景」

**做法**：每小节 2、4 拍（snare）按材质替换：

| 材质 | 音色 |
|---|---|
| water | splash（水花） |
| wood | tap（木块） |
| metal | clank（铁） |
| paper | rustle（纸） |
| cloth | swish（布） |
| kitchen | bowl（碗） |

**踩的坑**：metal 一开始用 `ring`，和接听关的铃声（也是 `ring`）撞名，测试里数出来的铃数翻倍。改成 `clank`。

## 阶段 7：十六分连点（失败）

**需求**：「八十六、十六八、二八、四个十六、附点」

**做法**：加节奏型库，4 关轮换。

**结果**：「不行，这样就变成了一个连点游戏」

**教训**：

- 密度 ≠ 难度
- 判断感来自**停顿**，不是「连打」
- 十六分连打让玩家「一直点」，不需要判断时机
- 留下的只有「二八」「切分」「附点」（都有停顿）

## 阶段 8：一句话规矩 + 变奏

**需求**：「一直在重复，重复 3 次就腻」

**做法**：

```
第 1-3 小节：一句 ×3          （建立规律）
第 4 小节：  加花             （第一次变化）
第 5 小节：  空               （呼吸）
第 6 小节：  回到原句
第 7-9 小节：整句挪半拍 ×3     （第二次变化）
第 10-11 小节：高潮 ×2
第 12 小节：  收
```

**遗留问题**：51 关都是这一套结构，只是落点不同。玩 5 关就会发现「又是这个套路」。

**待解决**：按关卡类型分配不同骨架，至少 5 种。

## 阶段 9：练习关

**需求**：「指导要让用户确认才算成功」

**做法**：

1. 每关前 2 小节 demo，灰点提示，不判定
2. 练完 `G.state = 'ready'`，`AudioContext.suspend()`
3. 显示「按一下开始」
4. 玩家按 → `resume()`，正式曲

**踩的坑**：

- 练习段让谱面整体后移 2 小节，但 `buildTrack` 的 `bars` 还是原来的
- 结果最后 2 小节没有鼓和旋律——「后面节奏没了」
- 修：`bars: G.lv.bars + 2`

**教训**：改时间轴偏移，要同步改所有依赖长度的地方（`totalOf`、`buildTrack`、测试断言）。

## 阶段 10：渲染缓存（卡音）

**问题**：偶发卡音。

**原因**：

- `drawRoom` 每帧重画整个房间（几十个形状）
- `drawBackdrop` 每帧新建两个渐变对象

主线程每帧多花几毫秒，`setInterval` 就排晚，音频节点错过时间窗口。

**修复**：

- 房间背景每关烘焙一次到离屏 canvas（按 `devicePixelRatio`，上限 2）
- 背景渐变同样缓存

## 教训汇总

1. **角色形状决定动作上限**——圆球做不出肢体动作，换火柴人才有「蹲、跳、踢」
2. **密度不是难度，停顿才是**——十六分连打是「连点」，不是「卡点」
3. **时间轴偏移要同步所有长度**——练习段 +2 小节，音乐轨道也要 +2
4. **加函数前先 grep 名字**——`mix` 重名浪费了一轮调试
5. **每帧重绘静态内容 = 卡音**——房间和背景要缓存
6. **练习关必须让玩家确认**——自动进正式曲等于没练
7. **判定窗口要留余量**——主线程卡一帧时，`reapMissed` 会吃掉晚到的输入（留 80ms）
8. **音乐调度要提前排**——lookahead 0.5 秒、每 25ms 检查，不能只提前 0.25 秒

## 还没解决的

- 51 关句子结构一样（最大问题）
- 练习段是正常速度，不是慢速
- 底鼓还是合成鼓（材质只换了 snare）
- 每关 30 秒，太短
- 没上过真机验证手感
