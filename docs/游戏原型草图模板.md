### 4.5 路网型地图（画的是线，不是格子）

手绘一堆斜线、每条代表一条路——这也算草图，而且**画的是拓扑**（谁和谁连通、有几条路、哪里是尽头），
比格子图更接近玩法。但它要变成数据，必须先把下面几件事说死：

| 必须定 | 为什么 | 现在的写法 |
|---|---|---|
| 一段路多宽 | 决定能不能并排走、能不能绕背 | 「6 格」→ 约 3 格半径 |
| 斜面怎么落格 | 45° 斜线在格子上是**楼梯**，不是直线 | `__`（楼梯 / 真斜向 / 不做格子） |
| 交叉是路口还是立交 | 画上看是 X，可能是桥下穿过去 | `__`（路口 / 立交 / 路口但单向） |
| 每条路都出 BOSS | 出 BOSS 是**随机挂在路段上**，还是路尽头固定房 | `__`（随机点 / 固定房） |
| 段数、段长、入口位置 | 这三个一改就是另一张图 | 约 __ 段 / 每段约 __ 格 / 入口在 __ |

**一个必须知道的后果**：6 格宽的两条斜路在格子上相交，路口会肿成一块约 12×12 的广场，
画上是干净的一个 X，跑起来是一大片空地。要么接受这个广场（当"路口小广场"用，正好放精英），
要么把路做成 45° 楼梯并限制只有十字/丁字接口。

> 这种图往往不是"一张固定的图"，而是**一套生成规则**（随机撒段 → 保证连通 → 每段挂 BOSS）。
> 那就该写生成器，而不是抄坐标：见 §5 最后一行。

**手绘图怎么进来（不用你报坐标）**：

```
python tools/trace-map.py 手绘.png docs/maps/名.segments.json 96   # 认线 → 线段
node tools/map-net.mjs docs/maps/名.segments.json 6 8              # 落格 + 补缝 + 数路口/死路/连通
```

- 第二个参数 `6` 是路宽格数，第三个 `8` 是**补缝容差**：手画的线头差一点点没接上是常态，8 格内自动接住。
- 输出会直接告诉你：路面占多少、几个路口、几条死路、有没有走不通的区域、全图直径几步。
- 现成样例：[`maps/hand1.png`](maps/hand1.png) → [`hand1-96.segments.json`](maps/hand1-96.segments.json)。

## 5. 落成代码（填完表才知道该写多长）

| 草图里的东西 | 落到哪 |
|---|---|
| 边长、视野 | `ROOMS[].size`、相机缩放（暗黑传奇 `data.js:359`） |
| `#` / `.` 分布 | `layout: 'open' \| 'cave'` + `world.js genRoom` |
| 怪的种类 | `ROOMS[].pool`（按 id 查 `MON`） |
| 数量、等级 | `ROOMS[].mobs`、`lvMin / lvMax` |
| 首领 | `boss: true, bossLv, bossName` |
| 地标 | 场景道具表（暗黑传奇是 `buildProps`） |
| **路网**（段数 / 宽度 / 角度 / 交叉） | **写生成器**：随机撒段 → 并查集保证连通 → 端点挂 BOSS 点。别把坐标抄死 |

## 6. 验收（写完拿这张单子打勾，别靠感觉）

- [ ] 从入口能走到出口 / 首领房（连通，没有必死的墙）
- [ ] 没有"必须穿过一整群怪才能过"的死锁
- [ ] 任意位置 10 步内至少有一个可做的事
- [ ] 至少 2 个地标，且回头能认出来
- [ ] 斜穿一遍 ≈ §4.2 写的步数（实测，不是估的）
- [ ] 一局时长落在 §4.2 写的区间里
- [ ] 720×1600（或 1280×720）截图一眼能看出哪是路

## 7. 已知的坑（这个仓库踩过的）

- **别按旧文档画**：暗黑传奇的图 1 文档写"48×48、视野 8"，代码里 `ROOMS` 实际是 20–26 —— 落数据时以能跑的代码为准，顺手把文档改回去。
- **别先画效果图**：地面是 45° 等距 + 菱形瓦片，手绘 45° 图永远和投影差一点，最后要么改图迁就代码、要么改代码迁就图。
- **别用"无尽"当一局长度**：先定 90 秒或 100 波，能测才叫原型。
- **没有地标的图，玩家会一直扫全局认路**——和 agent 读代码一个毛病，给两三个能当锚点的东西。
