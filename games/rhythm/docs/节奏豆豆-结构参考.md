# 节奏豆豆 · 结构参考（只抄结构，不抄素材）

> 目的：把《节奏天国》**关卡是怎么组织起来的**这件事拆清楚，对照我们现在的实现，指出差在哪、怎么补。
> 来源是社区对 3DS《节奏天国 Megamix》的逆向文档（[Tickompiler](https://tickompiler.readthedocs.io/en/latest/)），
> 不是猜的，每条都标了出处。

---

## 一、节奏天国的真实结构：**引擎 + 脚本**

Megamix 里有 **56 个引擎**（Spaceball = 0 … Super Samurai Slice = 0x37），
每个小游戏 = **一个写死的引擎** + **一份 Tickflow 脚本**。脚本只负责"什么时候发生什么"。

### 1. 时间单位是 tick，48 tick = 1 拍

> "A tick is the basic unit of time used in all Tickflow operations. **48 (`0x30`) ticks are generally equal to one beat**"
> —— [Concepts](https://tickompiler.readthedocs.io/en/latest/concepts.html)

所以 1 小节（4/4）= 192 tick；一个八分 = 24 tick。**全曲一套时间基准**，音乐、动画、判定都走它。

### 2. 脚本 = 一串顺序执行的函数调用，`rest` 就是"等"

```
rest 0xA2    // 3.375 拍
0x108<1>
...
rest 0x18    // 0.5 拍
rest 6       // 0.125 拍
```
—— Rhythm Tweezers 的实际代码（[Engines](https://tickompiler.readthedocs.io/en/latest/engines.html#rhythm-tweezers-3)）

**关键点：谱面不是"数据表"，而是一段可读的脚本。** 想改节奏就改这段文字，不用碰引擎。

### 3. 输入提示（cue）有统一接口

每个引擎都提供一个 `0x100` 系列的"出提示"操作，签名几乎都是 **`时间, 类型`**：

| 引擎 | 操作 | 含义 |
|---|---|---|
| Spaceball | `0x100 time, type` | `time` 个 tick 后球到，必须按 |
| Marching Orders | `0x100 time, type` | `time` 个 tick 后出现 `_ / 停 / 右转 / 左转` 提示 |
| Clappy Trio | `0x100 time` | `2*time` 个 tick 后拍手 |

也就是：**引擎只关心"还有多久要按"，不关心旋律。** 这是它和我们的**最大差别**。

### 4. 节奏型被封装成"子程序"（sub）

Clappy Trio 有 6 个异步子程序，全是同一个拍手句、只改间隔：

> `0x56` 两拍一次 · `0x57` 一拍 · `0x58` 半拍 · `0x59` 1/4 拍 · `0x5A` 1/8 拍 · `0x5B` 2/3 拍
> —— [Clappy Trio](https://tickompiler.readthedocs.io/en/latest/engines.html#clappy-trio-1)

**同一个节奏型，一个参数（间隔），六种难度。** 这是它 56 个引擎能撑起上百关的根本原因。

### 5. 练习段的做法：关输入，不是关音乐

> "note that **input is usually disabled using `input` at the start of a pattern, and re-enabled 3 beats later**"
> —— [Rhythm Tweezers 注释](https://tickompiler.readthedocs.io/en/latest/engines.html#rhythm-tweezers-3)

音乐照放、动画照走，只是前 3 拍不判定。这比"先放一段 demo 再开始"更自然——**玩家一开始听见的就是正式曲**。

### 6. 每关有一个"技能星"（Skill Star）

`0xAE` 专门管这颗星，判定条件写在脚本里（Quiz Show 里是分数达标）。
效果是：**同一关有"过关"和"完美"两个目标**，重玩有理由。

## 二、我们现在是什么

| 概念 | 节奏天国 | 节奏豆豆（`games/rhythm/`） |
|---|---|---|
| 引擎 | 每关一个 `engine`（0x00–0x37） | 每关一个 `SCENERY[id](ctx)` + 一份 scene 配置（`scenes.js`） |
| 脚本 | Tickflow 文本，`rest` 控时 | `patternOf(chart)` 用 JS 模板**现算**（[scenes.js:65](games/rhythm/scenes.js#L65)） |
| 时间基准 | 全局 tick（48/拍） | 秒 + `bpm` 换算，谱面用"小节 × 八分格" |
| 节奏型 | sub，可传参复用 | 模板 `one/phrase/rounds/tail/half/mix`，**有几关就直接写死 `keep.*` 表** |
| cue | `0x100 time,type` | 音符对象 `{t, judged}`，判定窗口 `WIN = {perfect:80, good:150, miss:220}`（[rhythm-core.js:24](games/rhythm/rhythm-core.js#L24)） |
| 练习 | `input` 关 3 拍 | 前 2 小节 demo + 玩家确认（比它更啰嗦，但可用） |
| 完美星 | `0xAE` 技能星 | **没有** |

**一句话**：我们的"引擎/脚本"是混在一起的，而且**谱面是算出来的，不是写出来的**。
所以 51 关看起来都像同一关——开发记录里那条"最大问题（句子结构一样）"，根子在这儿。

---

## 三、差距只有三条

1. **谱面不能独立编辑**：模板参数 + `keep` 表，改节奏要改代码。
2. **节奏型不能跨关传参**：`rounds` 只能改 `hits` 数组，没有"同一句、换间隔"这种自由度。
3. **没有"完美"这个第二目标**：只有 S/A/B 评级，没有单点高光。

## 四、怎么补（按性价比排序）

### 4.1 谱面抽成文本：`games/rhythm/charts/<id>.chart`

一格 = 一个八分音符，一行 = 一小节。`x` 按、`.` 空、`*` 技能星段、`o` 只演不判（练习）。

```
# kick   bpm=104   bars=12
x...x...   # 1  一句
x...x...
x...x...
x...x.x.   # 4  加花
........   # 5  呼吸
x...x...
....x...   # 7  挪半拍 ×3
....x...
....x...
....x.x.
....x.x.
x...x...   # 12 收
```

**解析器只要 30 行**：按行切、去注释、每行 8 格转成 `[bool×8]`。
输出结构跟现在 `patternOf` 返回的完全一致（`[[bar],[bar],…]`），所以**下游一行代码都不用改**。

### 4.2 节奏型抽成 `subs.js`

```js
export const SUBS = {
  'clap': { gap: 2, bars: (g) => { /* 同一句，间隔 g 个八分 */ } },
  'rounds': { hits: [0,2], gapBar: true },
};
```
谱面里写 `# use: clap gap=1`，`gap` 就是难度旋钮。
Clappy Trio 的六档（2 / 1 / ½ / ¼ / ⅛ / ⅔ 拍）直接变成 `gap=4 / 2 / 1 / 0.5 …`。

### 4.3 加技能星

谱面上标 `*` 的那一小节，全 perfect 就给星。我们 `grade()` 已经在数 perfect（[rhythm-core.js:137](games/rhythm/rhythm-core.js#L137)），
加个 `if (bar 有星 && 该 bar 全 perfect) G.star = true` 就行，成本半小时。

## 五、51 关的骨架分配（治"都是同一套"）

现在 51 关共用一条句子骨架：`一句×3 → 加花 → 呼吸 → 挪半拍×3 → 高潮×2 → 收`（[scenes.js:71-101](games/rhythm/scenes.js#L71-L101)）。
拆成 5 种骨架，**每 10 关里至少 3 种不同**：

| 骨架 | 结构 | 适合的模式 | 关卡数 |
|---|---|---|---|
| **A 模仿** | 做一遍 → 跟一遍（×3）→ 变奏 | `echo` | 16 |
| **B 卡点** | 空 2 拍 → 落 1 下（×6） | `beat` | 18 |
| **C 配对** | 左右各一下，中间留空 | `pair` | 8 |
| **D 变奏** | 前 6 小节原样，后 6 小节挪半拍 | `half` | 6 |
| **E 混编** | A+B 各取一半 | `mix` | 3 |

规则：**同一骨架不连排 3 关**，且每 10 关必换 BPM 区段。

## 六、明确不抄的东西

| 不抄 | 原因 |
|---|---|
| 贴图 / 音效 / 字体 | 版权属任天堂。仓库是公网 Pages，不能放 |
| Tickflow 语法本身 | 它的 opcode 是 3DS 字节码编号（0x100 系列），搬过来没意义 |
| 56 个引擎 | 我们一关一个 `SCENERY` 已经是等价物，不需要重写 |

**只抄三件事：时间轴独立成文本、节奏型可传参复用、每关一个完美目标。**
