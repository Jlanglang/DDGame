## 一、目标与非目标

### 1.0 第一版范围（1–10 级）

**只做 1–10 级的内容，后面的等级段等这套跑通再扩。**

| 项 | 第一版（现在做） | 以后（M2.6+） |
|---|---|---|
| 世界 | **128×128**：城镇 + 荒田 + 1 个洞口 | 256×256 + 森林/荒原 |
| 主题 | **field + cave 两套** | field/forest/waste/cave 四套 |
| 怪物 | **鸡 Lv1 / 稻草人 Lv3 / 野狗 Lv5 / 野猪 Lv7 + BOSS 巨型稻草人 Lv10**（5 只） | 13 只 + 4 个 BOSS |
| 洞穴 | **稻草垛洞 1 个** | 3 个 |
| NPC | 商人 / 村长 / 书商 / 仓库 | 同 |
| 玩家 | 20 帧（待机 2 + 挥砍 3） | 补走路/施法 |

> 1–10 级正好对上现有 `data.js` 的 4 张图：鸡鸣村外 / 荒田 / 荒田深处 / 稻草垛洞。

### 1.1 目标画面（参考传奇，不追求像素级复刻）

- **45° 立体**：地面是 3D 地形（材质平铺 + 光影），房子是一整张手绘立牌，有正面和屋顶，**但不需要阴影、不需要房前房后遮挡**。
- **一张图连续走**：从城镇中心走到野外，再走到洞口，**不弹房间列表**。
- **动作看得清**：待机 + 挥砍 3 帧；走路用代码浮动，施法复用挥砍 + 特效。
- **有地标**：城镇有房、摊位、水井、篝火；野外有路、树、石头；洞口有入口标志。
- **风格**：干净的手绘/厚涂 2D（参考传奇），不是现在的程序化像素。

> **玩法零改动**：战斗、掉落、商店、任务、挂机、升级曲线、数值表全部不动。
> 这轮只改两件事：**"看起来是什么样"** 和 **"世界怎么连"**。

### 1.2 明确不做（这轮）

- ❌ 装备分层（武器/衣服不叠在角色上，角色整张画）
- ❌ 走路 / 施法 / 受击 / 死亡帧（第一版用代码浮动、特效、白闪、淡出补）
- ❌ UI 皮肤（雕花边框、技能球、聊天框、小地图美化）
- ❌ 天气、昼夜、动态光照
- ❌ 8 方向（先 4 向，8 向留到 M2.6）
- ❌ 全 3D 模型（低模/体素角色不做，角色是 2D 立牌）
- ❌ 多人/服务器
- ❌ 直接使用《热血传奇》素材（版权）

## 二、技术路线（Three.js HD-2D）

### 2.0 引擎定案：浏览器 + Three.js + HD-2D

**主人的底线：打开浏览器就能玩，不安装。** 这条决定了几件事：

| 项 | 定案 | 理由 |
|---|---|---|
| 运行方式 | **纯静态网页**（`index.html` + js + png） | GitHub Pages 直接开；双击 `index.html` 也能玩 |
| 渲染 | **Three.js（WebGL2）** | 真深度、动态光、正交相机，手机浏览器都支持 |
| 画面 | **HD-2D**：3D 地形 + 2D 立牌 | 保住 AI 手绘素材，又有立体感 |
| 构建 | **运行时零构建** | `vendor/three.iife.js` 打包一次提交进仓库 |
| 存档 | localStorage（现有） | 无账号、无服务器 |
| 回退 | WebGL 不可用 → 现有 Canvas 顶视版 | `?engine=canvas`，老设备也能玩 |

**两个必须提前避开的坑**：

1. **`file://` 不能用 ES module**：Chrome 会以 CORS 拦掉 `import`。所以 Three 用 **IIFE 单文件**（`vendor/three.iife.js`，esbuild 打一次），`index.html` 里用普通 `<script>`。
2. **`file://` 不能 fetch**：`TextureLoader` 走 `new Image()` 没问题；但 `GLTFLoader` / `fetch(json)` 会被拦。所以**不用外部 3D 模型文件**，房子/地形用代码生成几何 + 贴图，数据全部写在 JS 里。

### 2.1 场景与相机

- 正交相机，**固定 45° 俯角，不能旋转**（一转就看出角色是纸片）。
- 世界单位：**1 格 = 1 单位**，地面在 `y=0`；高度只影响视觉，碰撞仍在 2D 网格。
- 相机跟玩家平滑移动，夹在 128×128 世界边界内。
- 视野：**1280×720 逻辑（16:9 横屏）**，正交视锥按这个比例算；**1 格 = 48 屏幕像素**，可见约 **27×15 格**，`zoom` 可调。
- 窗口大于 16:9 时两侧留边（letterbox），小于时等比缩小；**不拉伸**。
- `renderer.setPixelRatio(Math.min(devicePixelRatio, 2))`，别在手机上按 3 倍渲染。

### 2.2 地形

- **区块（chunk）16×16 格**，每个 chunk 一个 `PlaneGeometry`（或 16×16 分段），LRU 保留 12 个。
- **地面材质**：一张 shader 混 4 张无缝贴图（草 / 土 / 石 / 水）+ 一张 splat 权重图（RGBA）。
  权重由 `terrain[y][x]` 在 CPU 端算好，写进顶点色或一张小纹理。
- **道路 / 装饰**：直接刷进 splat 权重（路 = 土权重 1），或叠一层 decal 面片。
- **房子**：**整栋一张手绘立牌**（AI 出图），锚在底部；不做 3D 盒子、不做三面贴图。
- **树 / 石头 / 摊位**：同样是 2D 立牌，去背 PNG。
- **高度图（可选）**：以后再做悬崖/台地；这轮地面先平。

### 2.3 层序：不做阴影、不做遮挡

主人明确说过：**影子和房前房后遮挡无所谓**，这轮全部去掉。

- **固定层序**（从下到上）：
  1. 地面
  2. 建筑 / 道具 / 树（背景立牌，永远在角色后面）
  3. 角色 / 怪物
  4. 技能特效 / 飘字
  5. DOM UI
- **不启用 shadow map，不画脚底影子**（以后想加再说）。
- **不做遮挡淡出**，也不做"人物被房子挡住"的逻辑——**玩家永远可见**，不会在屋檐下消失。
- 透明立牌只按层序排，**不按到相机的距离排序**，省掉一整套透明排序。
- 代价：人走到房子"后面"时，会看起来浮在屋顶前面——**接受，不修**。

### 2.4 连续世界（第一版 128×128）

- 世界 **128×128 格**，一张图，不切房间。
- chunk 网格按需加载/释放，规则和 2D 版一样：视野内保留，离开释放。
- 第一版只放 1–10 级区域：

| 区域 | 范围 | 内容 |
|---|---|---|
| 城镇「鸡鸣村」 | 中心 48×48 | 房子、摊位、水井、篝火、NPC、城门 |
| 野外「荒田」 | 西/南 | 草地、土路、鸡/稻草人/野狗/野猪 |
| 洞口「稻草垛洞」 | 北 | 走上去进洞穴地图，BOSS 巨型稻草人 Lv10 |
| 预留 | — | 森林/荒原放 M2.6，先把坐标留出来 |

- **洞穴**：独立 `64×64` 地图，同样 3D 渲染，走到洞口淡入切图（不弹列表）。
- **小地图**：继续用 2D canvas 俯视图，不做美化。

### 2.5 动作系统（第一版：待机 + 挥砍）

**第一版不做走路帧、不做独立施法帧。** 目标压到 **4 向 × 5 帧 = 20 张**（原计划 76 帧）。

| 动作 | 帧数 | 来源 | 说明 |
|---|---|---|---|
| 待机 | 2 | 画 | 呼吸起伏，2fps |
| 走路 | **0** | 代码 | 用待机帧 + 上下浮动 2px + 朝向前倾，不画帧 |
| **挥砍** | **3** | 画 | 前摇 / 挥出 / 收势；普攻、半月、烈火**全用这一套** |
| 施法 | **0** | 复用 | 复用挥砍帧，靠特效（火焰/月牙）区分 |
| 受击 | **0** | 代码 | 白闪 + 后仰位移 0.1s |
| 死亡 | **0** | 代码 | 缩小 + 淡出 0.4s，不画倒地帧 |

- 每向 5 张（待机 2 + 挥砍 3），4 向 = **20 张**；想再省就 2 向 + 镜像 = **10 张**。
- 走路"滑步"用代码补偿：移动时 `bob = sin(t*8)*2px`、身体朝移动方向前倾 2°；这套代码 0.5 天。
- 立牌贴图是序列帧：`texture.offset` 换格，或每帧一张 `CanvasTexture` 缓存。
- 方向：4 向 = 屏幕的 **NW / NE / SE / SW**，对应格子的 **北 / 东 / 南 / 西**；WASD 一一对应。
- 状态机：`idle → walk → attack/cast → recover`，不打断移动；时长对齐现有 `COMBAT_MS`。

### 2.6 输入

- 点击/触摸：从相机发一条射线，打到 `y=0` 地面 → 世界坐标 → 格子 → 走现有 BFS。**手感偏差 ≤ 半格**。
- 键盘 WASD/方向键：保持 8 向移动。
- 所有触摸逻辑（`pointerdown/move/up`、`setPointerCapture`、`touch-action:none`）**一行不改**，只换坐标换算。

### 2.7 打开即玩 / 降级

| 场景 | 行为 |
|---|---|
| 双击 `index.html`（`file://`） | 能玩；脚本全是普通 `<script>`，不 fetch |
| WebGL2 可用 | Three.js HD-2D |
| WebGL 不可用 / 老设备 | 自动提示 + `?engine=canvas` 回退现有顶视版 |
| 低端机 | 低画质档：关后期、`pixelRatio=1` |
| 首屏 | Three 约 150KB gzip + 首批贴图/立牌 ≤ 1.5MB |

### 2.8 宽屏 UI 布局（1280×720）

**竖屏改横屏，UI 全部重排。** 皮肤还是现在这套 CSS，不雕花。

| 位置 | 内容 |
|---|---|
| 左上 | 等级 / 金币 / 装备摘要 / 日志（可折叠） |
| 右上 | 小地图（2D 俯视，180×180）、静音/角色/菜单 |
| 左下 | 虚拟摇杆（128×128）+ 血/蓝/经验条 |
| 右下 | 技能栏 8 个按钮一排：攻击 / 半月 / 烈火 / 红药 / 蓝药 / 挂机 / 交谈 / 撤退（每个 ≥ 56×56） |
| 中间 | 游戏画面；面板（商店/角色/背包/任务）居中弹出，最大宽 720 |
| 手机竖屏 | 覆盖层提示"请横屏游玩"，不强制，可继续竖屏（letterbox） |

- 画布固定 1280×720 逻辑，CSS 等比缩放填满窗口；窗口不是 16:9 就上下/左右留边。
- DOM UI 跟着 stage 缩放，**文字保持清晰**（DOM 不受 canvas 缩放影响）。
- 触摸目标 ≥ 56×56 CSS px；摇杆和技能栏在拇指区。
- **输入坐标全部按 1280×720 重算**，现有 `test-input.js` 里的 720×1120 常量要改。

## 三、素材规格 v3（HD-2D）

> 素材可以慢慢来，但规格先定死；Cursor 按这个出，不要自创尺寸。

### 3.1 地形（3D 地面用材质，不用菱形瓦片）

| 项 | 规格 |
|---|---|
| 材质 | 每主题 4 张 **1024×1024 无缝贴图**：草 / 土路 / 石地 / 水 |
| 视角 | **top-down 平铺**（不是 iso 菱形），shader 里混合 |
| 过渡 | 不需要边角瓦片：splat 权重由代码按 `terrain[y][x]` 生成 |

> 这是换 Three.js 后**变简单**的部分：省掉了 16 边 + 4 内角 + 菱形对齐，AI 只出材质，接缝交给 shader。

### 3.2 建筑与道具

| 类型 | 规格 | 数量（先做城镇） |
|---|---|---|
| 房子 | **整栋一张立牌 192×224**（透明/洋红底），锚在底部 | 4（杂货铺 / 村长家 / 书商 / 仓库） |

### 3.3 角色

| 项 | 规格 |
|---|---|

| 显示 | 96×120（1 格 = 48px 时约 2.5 格高） |
| 不做 | 装备分层；走路/施法/受击/死亡帧（代码补） |
| 再省 | 2 向 + 镜像 = **10 张** |

`待机 1 / 走 1 / 攻击 1 / 死亡 1`，每只 **96×120**，第一版 5 只 = 20 格。

### 3.5 素材批次

| 批 | 内容 | 用途 |
|---|---|---|
| A | 城镇地形（field）+ 4 栋房 + 12 小物件 + 3 树 | **垂直切片** |
| B | 荒田（复用 field 材质）+ 5 只怪 × 4 帧 + 洞口 | 1–10 级野外 |

### 3.6 出图方式：AI 为主，程序化只做"底"

**不做纯程序化了。** 主素材走 AI 出图，分工变成四块：

| 谁 | 干什么 |
|---|---|
| **AI 出图** | 材质、房子、树、道具、角色、怪物、洞口 |
| **Cursor / Python** | 抠底、裁切、锚点对齐、拼图集、写 manifest、接线、校验 |
| **程序化** | 无缝纹理底、splat 权重、几何体、占位图 |
| **人工** | 挑图、修关键帧、定风格、验一致性 |

两种交接模式，Cursor 两种都支持：

- **模式 A（默认）**：主人用 Midjourney / SD / 即梦 / GPT-image 出图 → 丢进 `assets/iso/raw/` → Cursor 跑后处理。
- **模式 B**：Cursor 配了出图 API → 按 §3.8 的提示词直接生成到 `raw/`，再跑同一套后处理。

### 3.7 出图硬规格（8 条）

1. **一图一物**：不要角色表、不要九宫格、不要拼图。
2. **45° 等距、2:1、正交**：提示词里必须写 `isometric 2:1, 45-degree, orthographic`。
3. **纯色洋红底 `#FF00FF`**：不要透明底（AI 的透明不可信），后处理抠。
4. **主光左上、不画投射阴影**：全批统一，不然拼一起像两个游戏。
5. **不要文字 / UI / 水印 / 边框**。
6. **生成 1024 以上**，后处理再缩到目标格（房子 192×224、角色 96×120）。
7. **同批同 seed / 同参考图 / 同风格词**：风格漂移是 AI 出图最大的坑。
8. **锚点留白**：底部留 8–12px 给脚底，别贴边。

### 3.9 分资产提示词

### 5.3 性能预算

**配置基线（主人 2026-10-27 定）**

| 档 | 配置 | 目标 |
|---|---|---|
| **标准（验收基准）** | **RTX 3060 / 16GB / 1080p 144Hz / Chrome** | **144Hz 满帧，GPU 帧时间 < 3ms** |
| 最低（能玩） | 集显 / 手机 / 低画质档 | ≥ 30fps |
| 不追求 | 4K 全屏、光追、多屏 | — |

- 16GB 内存对网页游戏是富余；**浏览器整体内存预算 < 1GB（含素材）**，显存 < 1GB。
- 素材可以按 **1K～2K 贴图**做，不用为了省内存压到 512。
- 真正要盯的是 **draw call 和每帧 JS**，不是显存。

| 项 | 目标 |
|---|---|
| 帧率（PC 3060） | 144Hz 满帧；100fps 轻松 |
| GPU 帧时间 | < 3ms |
| 单帧 draw call | < 150 |
| 三角形 | < 60k |
| chunk 缓存 | ≤ 12 个 |
| 浏览器内存 | < 1GB（含素材） |
| 首屏 | ≤ 3s；Three + 首批素材 ≤ 1.5MB |

> **测帧方法**：加 `?stats=1` 叠一层 `frame time / draw calls / triangles`；Chrome 测试时可用
> `--disable-frame-rate-limit` 看上限，正式玩仍按显示器刷新率 vsync（60Hz 就是 60，144Hz 才能 144）。
> **帧时间稳定比平均帧数重要**：3060 上掉到 100fps 不算问题，忽高忽低才是问题。

### 9.5 为什么"玩法已固定"还要 60+ 人天

玩法固定只省掉"设计系统 + 数值 + 存档结构"那部分（约 30～40%）；**这次换的是运行时**，代码 40～52 天里没有一天花在战斗/掉落/商店上——那些一行不改。

| 钱花在哪 | 人天 | 说明 |
|---|---|---|
| 新渲染器 | 14～16 | Three 场景、正交相机、地面 splat、立牌、材质、降级 |
| 连续世界（1–10 级） | 10～13 | 128×128 生成、chunk 流式、5 怪、1 洞穴、存档、小地图 |
| 动画 | 5～7 | 20 帧、idle/attack/dead、走路浮动、接战斗 |
| 宽屏 UI + 输入 + 测试 | 10～14 | HUD 四角布局、摇杆/技能栏、射线拾取、回归 |
| 打磨/联调 | 4～6 | 雾、色阶、性能、收尾 |

**素材 18～25 天也不是"生成"**：生成只是第一步，后面是选图、抠图、缩放、对锚点、拼图集、审图、修一致性。
按 80+ 个可用素材、每个 15～25 分钟算，光机械处理就 20～35 小时 = 3～5 人天；角色 20 帧只占 1～2 天。

**AI 写代码能快 20～30%，但调试、真机、审美返工基本会吃回去**，所以按人天算不按"AI 魔法"算。

### 9.6 想快可以砍（按代价排序）

| 砍法 | 省 | 代价 |
|---|---|---|
| 连续世界 → 保留房间制 | 10～13 天 | 失去"一张图走到底"，回到传送门列表 |
| 宽屏 → 保持竖屏 | 4～6 天 | PC 上中间一条，体验差 |
| 4 向 → 2 向镜像 | 1 天 | 侧面像正面 |
| 素材先用占位 | 12～20 天 | 能跑不能看 |

全砍的"最小可看版"约 **26～33 人天（5～7 周）**：Three 切片 + 房间制 + 20 帧 + 占位素材。
但那就不是主人要的那个东西了。

> 只解决一件事：**让 3D 版能当默认、过 §四 M2.0 验收**。

### 10.0 实测基线（2026-10-27 18:00，本机）

| 项 | 结果 |
|---|---|
| 逻辑 / 射线 / 输入 | 388 / 487 / 6，全过 |
| 3D 真点击 | 点 (59,64) → 人物走到 (59,64)，偏差 0 格 |
| 3D 帧 | draws 37 / tris 74；单帧 JS **9.8ms**（144Hz 预算 6.9ms） |
| 小地图 | 128×128 每帧全量重画（约 1.6 万格） |
| 素材 | 18 个文件 0.9MB；P0 齐，P1/P2 20 项 SKIP |
| 提交 | f3ef444 已提交；线上入口仍是 2D（3D 要 `?engine=three`） |

**三条硬伤**（都不是"再等等"能解决的）：

1. **怪图集映射错**：`mobs.png` 是 8 列 × 7 行、一行两只怪；3D 按"行号 = 怪物序号"取图 → 13 种只有鸡对（稻草人显示成狗）。切片里就有，测试没覆盖。
2. **3D 不是默认**：游戏库卡片和 `wanted()` 都要 `?engine=three`；线上也没更新。
3. **相机不夹边界**：走到世界边缘就是蓝底；主城没有房子，墙只是画在地上的灰块。

### 10.1 A 类：不依赖美术（先做，约 2～2.5 天；A9 可后置）
